# CreatorOS PRD

## 1. 产品一句话

CreatorOS 是面向自媒体创作者的增长与内容生产工作台：通过监控赛道流量信号、拆解爆款内容、生成账号定位和内容方案，帮助短期起号创作者快速复制有效打法，也帮助长期创作者形成可持续内容系统。

## 2. 目标用户

### 2.1 短期起号创作者

- 目标：尽快起号、验证赛道、获得第一批流量。
- 痛点：不知道做什么选题，不知道哪个内容形式更容易起量，复制爆款时容易只抄表面。
- 核心价值：发现正在上升的内容信号，拆解可复用结构，快速生成可发布草稿。

### 2.2 长期经营创作者

- 目标：建立清晰定位、持续生产内容、形成商业化资产。
- 痛点：定位摇摆，内容生产低效，热点和账号人设脱节，多平台分发消耗精力。
- 核心价值：给出定位、栏目、打法、执行 Agent，并把赛道数据和账号定位结合生成可落地内容。

### 2.3 小团队/工作室

- 目标：批量管理多个账号，提高选题和内容生产效率。
- 痛点：内容流程分散，复盘困难，选题、撰稿、审核、发布之间缺少统一协作。
- 核心价值：统一趋势、策略、草稿、审批、发布状态。

## 3. 核心问题

1. 起号难：创作者缺少可量化的赛道流量信号，无法判断做什么更容易起量。
2. 制作慢：选题、脚本、标题、封面方向、分发文案需要反复手工完成。
3. 定位虚：长期创作者知道要定位，但难以把定位转成具体栏目、选题、话术和执行节奏。
4. 多平台累：确认内容后仍要手动适配并发布到多个平台。

## 4. 产品目标

### 4.1 MVP 目标

- 让用户在 10 分钟内完成一次账号定位。
- 让用户能把热点视频拆成可复用 prompt 包。
- 让用户基于一个爆款信号生成一篇可修改内容草稿。
- 让用户能把内容从“生成”推进到“确认”和“发布队列”。
- 用本地模拟数据跑通闭环，保留真实平台数据和发布 API 的接入位置。

### 4.2 非目标

- MVP 不做真实爬虫和绕过平台限制的自动化发布。
- MVP 不承诺内容一定爆火。
- MVP 不做复杂团队权限、计费、企业工作流。

## 5. 关键用户旅程

### 5.1 快速起号模式

1. 用户选择平台和赛道。
2. 系统展示近期高流量/高增长信号。
3. 用户选择一个爆款信号。
4. 系统用爆款逆向器拆解钩子、结构、镜头语法、情绪曲线，并生成 prompt 包。
5. 用户把 prompt 包交给内容 Agent，生成同结构但不同表达的内容草稿。
6. 用户修改后确认，进入发布队列。

### 5.2 长期经营模式

1. 用户填写赛道、目标人群、个人优势、变现方向、内容风格。
2. 系统生成定位、一句话价值、内容支柱、30 天打法。
3. 系统持续展示该赛道信号，并判断哪些信号适合该账号。
4. 用户选择信号，爆款逆向器输出可复用 prompt 包。
5. 内容 Agent 输出选题、脚本、图文结构、发布文案。
6. 用户确认后分发到目标平台。

## 6. 功能范围

### 6.1 趋势雷达

- 平台维度：抖音、小红书、B站、视频号、公众号。
- 内容形态：短视频、图文、长文、直播切片、播客切片。
- 信号字段：热度、增速、可复制度、适配赛道、爆款钩子、内容结构。
- MVP 数据源：内置种子数据 + 用户手动添加监控关键词。
- 后续数据源：平台开放 API、第三方数据服务、用户授权账号数据。

### 6.2 账号定位

- 输入：赛道、人群、阶段、优势、目标、语气、平台。
- 输出：定位句、差异化护城河、目标人群承诺、内容支柱、打法建议、Agent 任务清单。
- 评价：是否能指导选题、标题、内容结构、发布频率。

### 6.3 内容 Agent

- 输入：账号定位、选中爆款信号、平台、内容形态、目标。
- 输出：标题/开头钩子、脚本大纲、正文/口播稿、图文分镜、标签、CTA、平台适配建议。
- 状态：草稿、已确认、已排队、已发布。

### 6.4 爆款逆向器

- 输入：热点视频链接、标题、字幕/口播稿、观察笔记、平台、赛道方向、目标账号、角色设定。
- 输出：钩子类型、核心张力、情绪曲线、可复用结构、镜头语法、复用信号、改写边界。
- Prompt 包：角色 prompt、脚本 prompt、分镜 prompt、视频生成 prompt、封面 prompt。
- MVP 能力：基于用户输入的文本信息做结构化逆向和 prompt 生成。
- 后续能力：接入视频抽帧、ASR 字幕、OCR、评论高频问题、平台数据表现和版权风险检测。
- 合规要求：只复用结构和表达策略，禁止直接搬运原文案、原画面、原人物或受版权保护素材。

### 6.5 发布队列

- MVP：模拟发布，记录平台、发布时间、状态。
- 后续：接入真实平台发布能力，遵守平台授权、审核和内容安全规则。

### 6.6 上架与增长

- 初始上架形态：独立站 + Product Hunt/国内创作者社群发布 + 等待名单。
- 关键素材：首页价值主张、功能截图、定价页、FAQ、隐私政策、用户协议。
- 首批获客：自媒体运营社群、AI 工具导航站、内容创业者私域、案例挑战赛。

## 7. 核心指标

- 激活：完成定位的用户比例。
- 价值达成：首次生成并保存草稿的用户比例。
- 效率：从选题到可发布草稿的平均耗时。
- 留存：7 天内再次生成内容或查看趋势的用户比例。
- 内容结果：用户标记“发布后表现好”的内容占比。
- 商业：付费转化率、每用户每月生成草稿数。

## 8. 商业模式

- 免费版：有限趋势查看、每月少量内容生成。
- Pro：更多监控赛道、更多生成额度、平台适配、发布队列。
- Studio：多账号、多成员、批量生成、复盘报告、API 接入。

## 9. 风险与约束

- 平台数据合规：必须使用开放 API、第三方授权数据或用户授权数据。
- 内容同质化：应强调结构复用和观点重写，避免直接搬运。
- 发布权限：平台自动发布需要 OAuth、审核机制和失败重试。
- AI 内容质量：需要保留人工编辑和确认步骤。
- 版权与素材：图文/视频素材生成和引用需标明来源或使用可商用素材。

## 10. MVP 验收标准

- 用户可以打开本地产品并看到趋势工作台。
- 用户可以填写定位表单并得到结构化定位结果。
- 用户可以输入热点视频信息并生成逆向 prompt 包。
- 用户可以选择一个趋势并生成内容草稿。
- 用户可以修改草稿、确认草稿、加入发布队列。
- 后端 API 可以持久化以上状态。
- 文档包含 PRD、原型说明、上架清单。

## 11. 后续路线

### Phase 1: MVP 验证

- 本地全栈产品。
- 内置趋势数据。
- 模拟内容 Agent 和发布队列。

### Phase 2: 数据接入

- 接入用户授权账号数据。
- 接入第三方热榜/内容数据服务。
- 增加内容表现复盘。

### Phase 3: 发布与协作

- OAuth 平台授权。
- 定时发布。
- 多账号、多成员审批。

### Phase 4: 智能增长系统

- 根据账号历史表现自动调整选题。
- 自动构建 30 天内容日历。
- 建立案例库、爆款结构库、复盘报告。
